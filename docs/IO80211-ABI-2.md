## Work queue and gate

`IO80211WorkQueue` inherits the IOWorkLoop virtual surface. Its slot 54 (symbol offset 0x1b0)
resolves to its own `runAction`; slots 65/66 (0x208/0x210) are `commandSleep(void*, unsigned long long)`
and `commandWakeup(void*)`. Word 67 is zero.

`IO80211CommandGate` slots 37-42 (0x128-0x150) are the two `runAction` overloads,
`runActionBlock`, `commandSleep`, `commandWakeup`, and `initWithParams(OSObject*, IO80211WorkQueue*)`.
Word 43 is zero. `allocWithParams(OSObject*, IO80211WorkQueue*)` is an exported nonvirtual factory.

`IO80211Controller::createWorkQueue` at 0xffffff8002226d0e simply clears EAX and returns.
`AppleBCMWLANCore::createWorkQueue` at 0xffffff8001591f70 uses either `IO80211WorkQueue::workQueue()`
or the bus-provided queue, retains the latter, and returns a boolean success check. Its return value
is not the queue pointer: `getWorkQueue` must also be mapped before declaring the subclass header.

`getWorkLoop()` (slot 211, `IO80211Controller::getWorkLoop` 0xffffff800222aec0) is a tail call of virtual `getWorkQueue()` (round 7:
`jmp [vptr+0xc68]`; Family `getWorkQueue` returns NULL, BCM's returns `ivars+0x7898`), so with an `IO80211WorkQueue` it is **not** the same
object as the provider's loop for our controller. `IO80211WorkQueue::workQueue()` = `new` (0x50 bytes) + `IOWorkLoop` ctor + virtual
`init` (slot 19) + registers itself as the default queue if none is set; `getThread` is overridden to return NULL. `IONetworkController::start` (round 6) calls `this->getWorkLoop()`, retains it, compares it
with `provider->getWorkLoop()`, and if different calls `ml_thread_policy(loop->getThread(), 1, 0x10000001)`;
`IO80211WorkQueue::getThread` returns NULL (stub), which panics (24H32). A subclass must override `getWorkLoop()` to return a loop
with a real thread (the provider's). `getWorkQueue()` stays the `IO80211WorkQueue` used by the gate/timers.

## Controller startup evidence

In `IO80211Controller::start` at 0xffffff800222283c, the observed order includes:

1. Inherited start and provider retain / registry plane attachment.
2. Reporter setup, control-path logging and fault-reporter attachment.
3. Ranging-manager allocation / initialization.
4. Virtual call through vptr +0xc68, corresponding to symbol slot 399 (`getWorkQueue`).
5. `IO80211CommandGate::allocWithParams(this, queue)` at 0xffffff8002222b1d;
   result stored at controller ivars +0x3b8 (ivars pointer at this +0x120), with a null check.

This is a selected observed sequence, not the complete initialization contract. Logger and fault
reporter requirements cannot be satisfied by blindly returning null from all pure virtuals.

## Interface and request names differ from the plan

No `IO80211SkywalkInterface::initWithController` symbol was found. The BCM interface instead exports
`initWithProviderAndParameters(AppleBCMWLANCore*, unsigned int, SkywalkInterfaceRole, bool,
unsigned char, apple80211_wme_ac*, unsigned int, CCLogStream*, CCFaultReporter*)`.
Its `start` calls `IO80211InfraInterface::start`, retrieves the work queue/logger, adds a work source,
and later calls `IO80211InfraInterface::registerInfraEthernetInterface` at 0xffffff800156aa90.
That registration takes a Skywalk RegistrationInfo, packet queues and packet buffer pools;
registration layouts and ownership still need mapping.

The plan's `getSCAN` and `setASSOCIATE` filters produce no BCM methods. Actual exported handlers include:

| Address | Handler / parameter |
|---|---|
| 0xffffff8001605dec | setWCL_SCAN_REQ(apple80211ScanRequest*) |
| 0xffffff8001606344 | setSCAN_CONTROL(apple80211_scan_control_params*) |
| 0xffffff8001608554 | setWCL_ASSOCIATE(apple80211AssocCandidates*) |
| 0xffffff800160dde8 | setDISASSOCIATE(apple80211_disassoc_data*) |

These names alone do not establish ioctl IDs, field offsets, sizes or authentication ownership.
`getCARD_CAPABILITIES` at 0xffffff80015f16ca writes a dword value 1 at output +0,
clears bytes +7..+0x17 and writes flags throughout that area. This proves at least a 0x18-byte
accessed extent, **not sizeof(apple80211_capability_data)**. No guessed struct is used in driver code.

## Analysis round 2 (cloud session, from the committed dump only)

Method: `tools/annotate_vcalls.py` turns `call [reg + 0xN]` into vtable slot names (slot = (N + 0x10) / 8). It does not know
the receiver class, so with several vtables the right name must be picked by what the object is; a few names above in raw
output (e.g. `findOrCreateFlowQueueWithCache` for slot 399 on an interface) are the **controller's** `getWorkQueue`, not the
interface's. Everything below was cross-checked against at least two call sites unless marked "single site".

### What `IO80211Controller::start` demands from a subclass (0xffffff800222283c)

1. `IOService::open(provider)` (slot 188) must succeed; it then retains the provider and attaches itself to an IORegistry
   plane that it creates (`makePlane`), so the object appears in an IO80211 plane.
2. **`getLogger()` (slot 426, pure virtual) is called and its result stored in a global (0xffffff80023f7a20) with no null check**,
   then `createIOReporters(provider)`. Every later log site in Apple's code does `getLogger()->shouldLog(level)`, so a null or
   bogus logger is a panic waiting to happen, not a harmless omission. A subclass needs a real `CCLogStream`. Apple's own
   code builds one with `CCPipe::withOwnerNameCapacity(IOService*, const char*, const char*, const CCPipeOptions*)` then
   `CCStream::withPipeAndName(CCPipe*, const char*, const CCStreamOptions*)` (seen in `IO80211SkywalkInterface::start`).
   Those belong to the CoreCapture kext, a further private dependency.
3. `setupControlPathLogging()`, `findAndAttachToFaultReporter()` (CCFaultReporter, same dependency).
4. Allocates `IO80211RangingManager` and calls `initWithController`.
5. **`getWorkQueue()` (slot 399) must already return a queue**: it is called three times and the result goes straight into
   `IO80211CommandGate::allocWithParams`, `IO80211TimerSource::allocWithParams` and `IO80211TimerFactory::allocWithParams`.
   `IO80211Controller::createWorkQueue` is *not* called from `start`; the subclass creates the queue itself before
   calling the base `start` (BCM does it in its own `start` and keeps it in its ivars).
6. `CreatePostOffice()` (slot 442) must return non-null (base implementation exists), `IO80211RNGAgent::withOptions`,
   `allocFramePool()`.
7. Boot-args read by the base class (useful for debugging): `wlan.disableIOCTL`, `wlan.useIOUCWhenPossible`,
   `wlan.ivars->fPanicOnIOCTL`, `wlan.disableEventSocket`.
8. The controller's private ivars live at `this + 0x120` (pointer), at least 0xb40 bytes: command gate at +0x3b8, post
   office +0xb08, timer factory +0xb10, RNG agent +0xb18, provider +0x360. Treated as opaque; never touched by a subclass.

### What the interface side needs (all from `AppleBCMWLANSkywalkInterface::start` and the two base `start`s)

* `IO80211InfraInterface` is the class a Wi-Fi driver subclasses (BCM: `AppleBCMWLANSkywalkInterface`), role via
  `SkywalkInterfaceRole`. Its `start` runs `IO80211SkywalkInterface::start`, creates `IO80211ScanManager`,
  `IO80211AVCAdvisory`, `IO80211DataPathInformAgent`, `IO80211BonjourOffloadAgent`, two timers, and `createLQMData`.
* `IO80211SkywalkInterface::start` opens the provider, builds a CCPipe/CCStream, creates a peer manager (virtual slot 354),
  a flow-queue database, and sets up power management (`PMinit`, `joinPMtree`, `registerPowerDriver`).
* The data path is registered at the end of the subclass `start` with
  `IO80211InfraInterface::registerInfraEthernetInterface(IOSkywalkEthernetInterface::RegistrationInfo*,
  IOSkywalkPacketQueue**, unsigned, IOSkywalkPacketBufferPool*, IOSkywalkPacketBufferPool*)`, which forwards to
  `IOSkywalkEthernetInterface::registerEthernetInterface`. So TX/RX means IOSkywalkFamily packet queues and two packet
  buffer pools, not `mbuf`s. The MAC address comes from slot 416 (`getSelfMacAddr`).
* The request entry point is `handleCardSpecific(IO80211SkywalkInterface*, unsigned long, void*, bool)` on the controller;
  `AppleBCMWLANCore::handleCardSpecific` copies a 0x28-byte request header and switches on a request code in a dword
  (codes `0x3f1`, `0x3f2`, `0x3f4`, `0x3f5` appear in its first comparisons). The Wi-Fi ioctls (`setWCL_SCAN_REQ`,
  `setWCL_ASSOCIATE`, ...) are separate virtuals of the controller, dispatched from the interface's `processBSDCommand` /
  `performGatedCommandIOCTL` (`routeIoctlToWcl` exists). The mapping code -> virtual is **not** extracted yet.

### Verdict on feasibility

A native subclass is possible (AirportItlwm does it on this macOS generation) but it is a large, private-ABI job, and
several pieces cannot be stubbed:

| Piece | Why it cannot be skipped | Missing evidence |
|---|---|---|
| `CCLogStream` logger | non-null required; used at every log site | CoreCapture class layouts / factory signatures, kext dependency version |
| `IO80211WorkQueue` + gate | `getWorkQueue()` non-null | exact constructor (`IO80211WorkQueue::workQueue()` is exported) - small |
| Instance sizes of `IO80211Controller`, `IO80211InfraInterface` | our `OSDefineMetaClassAndStructors` allocates `sizeof(ours)`; a header that omits the private ivars of the base allocates too little | the `MetaClass` constructors pass the size: disassemble `IO80211Controller::MetaClass::MetaClass()` etc. |
| Full virtual layout (464 + 468 slots) | a subclass vtable must be slot-exact | already in the dumps; a header can be generated mechanically from `*.vtable.txt` |
| `RegistrationInfo`, packet queues, buffer pools | the only TX/RX path | IOSkywalkFamily classes + struct layout |
| `apple80211_*` request structs | scan/join/status | per-handler field offsets |

Risk: every mistake is a kernel panic on a laptop that is also the daily driver, with a costly boot. The Ethernet front end
must stay the default, as planned.

### RegistrationInfo and queues: observed offsets, not a complete struct

The BCM interface start reads ivars via `this +0x128`. At registration:

* ivars +0x2a is the one-byte count of initial queues, copied from ivars +0x78
  into a temporary queue pointer array; two queues at +0x60/+0x68 are appended.
* Pool pointers passed in R8/R9 come from ivars +0x50/+0x58.
* RegistrationInfo pointer is preserved in R15; a word at +0x3c is read and
  subtracted from dwords +0x48/+0x4c before registration.
* The call at 0xffffff800156aa90 passes this, RegistrationInfo, the queue array,
  initial-count +2, and the two pools to registerInfraEthernetInterface.

Those accesses establish only field widths/extents, not names, full size or ownership.
Additional PCIe Skywalk pool/queue factory symbols and disassembly are included;
BCM PCIe-specific objects cannot be reused as this driver's queues.

## Analysis round 3 (cloud session)

### Controller header, generated and checked

`tools/gen_io80211_header.py abi/native-wifi/24H32/round3 > kexts/itlmt7925/io80211/IO80211Controller.h` produces
`IO80211Controller` as a class deriving from the SDK's `IOEthernetController`: 69 new virtuals (slots 396..464) in Apple's
order, pure slots named from `AppleBCMWLANCore`'s overrides, `start/stop/init/free/...` redeclared so `super::` reaches Apple's
implementation, and `static_assert(sizeof == 0x128)` (SDK `IOEthernetController` is 0x118, so Apple adds 0x10 opaque bytes; the
ivars pointer is at +0x120).

`python3 tools/check_io80211_header.py abi/native-wifi/24H32/round3` compiles a concrete subclass, asks clang for its vtable
layout (`-fdump-vtable-layouts`) and compares it slot by slot with Apple's vtable: **463 slots, 0 mismatches**. This also
proves that the whole inherited part (slots 2..395) of the SDK's `IOEthernetController` chain has the same layout as macOS
24H32. Six slots (327..332, `IONetworkController`) are named `_RESERVED*` in the SDK but have real names in Apple's binary
(`outputStart`, `setInputPacketPollingEnable`, `pollInputPackets`, `networkInterfaceNotification`, `allocatePacketNoWait`,
`setHardwareAssists`): same positions, so harmless unless a subclass overrides one of them.
Return types are not recoverable from mangled names; the generator marks every guessed one, and only the few methods a stub
overrides need to be right (to be confirmed from call sites).

### Logger: what the round-3 dump says

* `CCStream::withPipeAndName(pipe, name, opts)` returns null if any argument is null, then switches on the dword at
  `opts + 0` (values 0..4) to pick the stream class; one branch tail-calls `CCLogStream::withPipeAndName`.
* `CCLogStream::withPipeAndName(pipe, name, opts)` can be called directly: it reads the dword at `opts + 8` as a
  `CCStreamLogLevel`, rejects it if `isValidStreamLogLevel` fails, allocates the object and calls the virtual
  `initWithPipeAndName` (slot 270). That init requires non-null name and options, calls `CCStream::initWithPipeAndName`,
  allocates a ~0xaa0-byte state block (+0x90) and reads the boot-args `cc.debuglog.filter/.level/.flags`.
* Still unmapped: the rest of `CCStreamOptions` (size, other fields) and `CCPipeOptions`, and which concrete pipe class
  `CCStream::init` safe-casts the pipe to. Until then a logger cannot be built without guessing, which the stub must not do.

### 1. Logger contract (CoreCapture)

Apple builds a logger in four places: `IO80211Controller::setupControlPathLogging` (0xffffff8002222eda: pipe `ControlPath`,
streams `ioctl` / `event`, pipe+stream `LQMLogging`), `IO80211SkywalkInterface::start` (pipe `Interface_<bsd>_<unit>`,
stream `InterfaceLogs`) and `AppleBCMWLANCore::initDebugInfo` (a stream on an existing pipe). The controller stores the pipe at
ivars+0x38 (`this+0x120` -> ivars) and the streams at ivars+0x40 / +0x48; `getLogger()` must return a non-null `CCLogStream`.

**`CCPipe::withOwnerNameCapacity(IOService *owner, const char *ownerId, const char *name, const CCPipeOptions *)`**
(0xffffff80031bc9e4) switches on `opts->+0`: `0` -> `CCLogPipe::withOwnerNameCapacity`, `1` -> `CCDataPipe::...`, anything else
logs and returns null. `CCPipe::initWithOwnerNameCapacity` (0xffffff80031ba906, `round4/CCPipe-...asm.txt`) rejects names
whose `"ccpipe:" + name` exceeds 0x7f characters.

| `CCPipeOptions` (0x350 bytes, `IOMallocZeroData` + `bzero` by Apple) | width | read by | Apple's value |
|---|---|---|---|
| +0x000 type | u32 | `withOwnerNameCapacity` | 0 (CCLogPipe) in all three sites |
| +0x004 | u32 | `CCPipe::init` | 0 (not set) |
| +0x00c | u32 | `CCPipe::init` (if == 1, bit0 of +0x22c is consulted) | 0 (not set) |
| +0x010 | u64 | `CCPipe::init` | 0x10000 (ControlPath), 0x20000 (InterfaceLogs) |
| +0x018 | u64 | `CCPipe::init` | 0x6666 (ControlPath), 0x10000 (InterfaceLogs) |
| +0x020 | u32 | `CCPipe::init` | 0x3e8 |
| +0x024 | char[0x100] | name, copied with `strlcpy` | `ControlPath`, `Interface_%s_%u` |
| +0x124 | char[0x100] | second name (same text as +0x24 at ControlPath; `InterfaceLogs` for interface) | see left |
| +0x224 | u32 | `CCPipe::init` | 0x200000 (ControlPath) |
| +0x228 | u32 | `CCPipe::init` | 2 (ControlPath) |
| +0x22c | u32 | bit0 only, only when +0x0c == 1 | 0 |
| +0x238 | u64 | not read in the visible part of `init` | 0 |
| +0x244 | char[0x100] | subsystem string | `WiFi` |

Field *meanings* of +0x10/+0x18/+0x20/+0x224/+0x228 are not determined (only widths and values). Owner id string Apple passes:
`com.apple.iokit.IO80211Family`.

**`CCStream::withPipeAndName(CCPipe *, const char *name, const CCStreamOptions *)`** (0xffffff80031c0982) returns null on any
null argument and dispatches on `opts->+0` with a jump table (0xffffff80031c04dc): `0` CCLogStream, `1` CCDataStream,
`2` CCIOReportLogStream, `3` CCOSSerializeDataStream, `4` CCOSSerializeWithIOReportDataStream, `>4` null.
`CCLogStream::initWithPipeAndName` (0xffffff80031d0450) requires non-null name and options, then calls the base init; **it
safe-casts the pipe to `CCLogPipe` without a null check**, so the pipe must be a real `CCLogPipe` (type 0).
`isValidStreamLogLevel` (0xffffff80031d1959) accepts `-1..7` and `0x7f` only.

| `CCStreamOptions` (0x358 bytes) | width | read by | Apple's value |
|---|---|---|---|
| +0x000 type | u32 | `CCStream::init` jump table | 0 |
| +0x008 level A | u32 (`CCStreamLogLevel`) | `CCLogStream::withPipeAndName` validity check, init | -1 (set to 5 when `io80211isDebuggable`) |
| +0x00c level B | u32 | init (stored next to A; the larger is kept) | -1 |
| +0x018 | u64 | init (mask, or-ed with +0x20) | 0; 3 (ioctl) / 4 (event) when debuggable |
| +0x020 | u64 | init | 0 |

### 2. RegistrationInfo, queues and pools

**`IOSkywalkEthernetInterface::RegistrationInfo`** is 0x130 bytes. `initRegistrationInfo` (0xffffff8002987ed6) requires
`version == 1` and `size == 0x130`, zeroes +8..0x130 and sets +0 = 1, +4 = 0x130, +0x14 = 0x100, +0x24 = 0x22 and fills defaults
from virtuals of the interface (slot numbers of `IOSkywalkNetworkInterface`):

| offset | width | default / source |
|---|---|---|
| +0x08 | u32 | `getInterfaceFamily` (slot 309), 2 if 0 |
| +0x0c | u32 | `getInterfaceSubFamily` (310) |
| +0x28 | u32 | `getInitialMedia` (311), 0x20 if 0 |
| +0x30 | char * | `getBSDNamePrefix` (318), a built-in string if null |
| +0x38 | u32 | `getBSDUnitNumber` |
| +0x44 | u32 | `getMinPacketSize` (306), 0x2e if 0 |
| +0x48 / +0x4c | u32 x2 | `getMaxTransferUnit` (304), 0x5dc if 0 |
| +0x108..+0x10d | 6 bytes | MAC address, exported as the `IOMACAddress` property |

`copyRegistrationInfo` (0xffffff8002987fe4) accepts a block only if `version == 1` and `size >= 0x130`, copies 0x130 bytes and
sets `IOMACAddress` from +0x108 (null block -> `0xe00002c2`). `AppleBCMWLANSkywalkInterface::start` receives an already
initialised block; the only edits visible are `+0x48 -= u16(+0x3c)` and `+0x4c -= u16(+0x3c)` before registration. Other
bytes of the 0x130 block (+0x10, +0x18..0x23, +0x2c..0x2f, +0x34, +0x3c.., +0x50..0x107, +0x10e..) were not attributed.

**Registration chain** (all names exact):
`IO80211InfraInterface::registerInfraEthernetInterface` (0xffffff80022dcfce) ->
`IOSkywalkEthernetInterface::registerEthernetInterface` (0xffffff8002988078) -> `copyRegistrationInfo` ->
`IOSkywalkNetworkInterface::registerNetworkInterface(const RegistrationInfo *, IOSkywalkPacketQueue **queues, unsigned count,
IOSkywalkPacketBufferPool *, IOSkywalkPacketBufferPool *, unsigned)` (0xffffff8002981d7e). The last one builds the scheduling
objects itself: `IOSkywalkQueueSet::createWithQueues(queues, count, &info)` with `info = 3`, or `0xb` when
`IOSkywalkQueueSet::isWMMSchedModelCapable(queues, count)` (0xffffff800298ac44); then
`IOSkywalkLogicalLink::createWithQueueSet(&set, 1, &LogicalLinkInfo)` (info block copied from a 0x50-byte constant with
`version = 1`) and `registerNetworkInterfaceWithLogicalLink` (slot 284). A driver therefore supplies queues + pools, not a
queue set.

**Pools and queues as Apple's BCM PCIe layer creates them**
(`AppleBCMWLANPCIeSkywalk::allocSkywalkCommonResources` 0xffffff80014d93b0, `registerSkywalkInterface` 0xffffff80014d9bae):

* One common pool `AppleBCMWLANSkywalkPool` (`AppleBCMWLANPCIeSkywalkPacketPool::withName`, 0xffffff80014d76aa ->
  `AppleBCMWLANSkywalkPacketPool::initWithName` 0xffffff80016ebab0 -> `IOSkywalkPacketBufferPool::initWithName(..., type = 1)`,
  0xffffff800297cc58). A second pool `AppleBCMWLANSkywalkPoolMonitor` exists only for monitor mode. Options block, six u32 copied
  1:1 from the BCM options to the IOSkywalk options (the rest of the 0x30 stack block is zero):

  | | +0x00 | +0x04 | +0x08 | +0x0c | +0x10 | +0x14 |
  |---|---|---|---|---|---|---|
  | common | `d` | `d` | 0x800 | 1 | 0 | 1 |
  | monitor | 1 | 1 | 0x4000 | 1 | 0 | 1 |

  `IOSkywalkPacketBufferPool::initWithName` rejects `type >= 3`, requires non-null options, maps `+0x14` bit0 -> pool flag
  0x20 and bit1 -> 0x4 (+ byte `+0xb0 = 1`). The field names of +0x00..+0x10 are not determined; `+0` and `+4` are always
  equal, `+8` is a byte size (2 KiB / 16 KiB), `+0xc` is 1.
* `d`, and the queue capacities, come from `AppleBCMWLANBusInterfacePCIe::allocateSkywalkBusResource` (0xffffff800151cf22)
  -> `AppleBCMWLANPCIeSkywalk::withProviderAndCapacity(bus, a, b, c, d, e, logger, fault)`; with the five bus-state words at
  `bus_state+0x11d0..0x11e0` (`W0..W4`, source not determined here) equal to 0 the values are
  `a = 0x200`, `b = 0x400`, `c = 0x400`, `d = 0x1300 (4864 packets)`, `e = 0x800`. Otherwise
  `a = W3 ? W3 : (W1 ? W1+0x100 : 0x200)`, `t = W0 ? W0+0x100 : 0x200`, `b = 2t`, `c = W2 ? 4*W2 : 0x400`,
  `d = W4 ? W4 : 4a + t + 2c + (W3 ? 0x200 : 0x100)`, `e = 0x800`.
* Queues (all `...withProviderAndQueueInfoAndPool(bus, owner, ifId:u16, queueId, ..., capacity, pool, logger, fault)`;
  `ifId = IO80211SkywalkInterface::getInterfaceId()`):

  | queue | count | queueId | capacity | notes |
  |---|---|---|---|---|
  | `RxSubmission` (common, before any interface) | 1 | 0 | `c` | `ifId` 0 |
  | `TxSubmission` | `params.numTx` (4 for `AppleBCMWLANSkywalkInterface`) | 0..n-1 | `a` (`b` if `isLowLatencyEnabled`) | `apple80211_wme_ac` per queue from the interface: {0,1,2,3} |
  | `TxCompletion` | 1 | n | same as TxSubmission | |
  | `RxCompletion` | 1 | n+1 | `c` | |
  | `Multicast` | 0/1 (`params+0x38`) | - | - | `withProviderAndQueueInfo`, no pool |

  `AppleBCMWLANSkywalkInterface::withProvider` fixes `numTx = 4`, ACs `{0,1,2,3}`, multicast enabled
  (`initWithProviderAndParameters` rejects `numTx > 4`).
* Constraints enforced by the IOSkywalk base classes (`round4/IOSkywalk*Queue-initWithPool.asm.txt`):
  `IOSkywalkPacketQueue::initWithPool(pool, x, kind, capacity, queueId, target, action, refcon)`: `kind` in 1..3 (Tx = 1,
  Rx = 2 in Apple's callers), `queueId < 0x10000`; `Tx submission`: capacity >= 8, flags <= 0x1f, non-null dequeue callback,
  `x` = 4-byte table value indexed by AC (`{0, 0x00100080, 0x00380100, 0x00400180}`, meaning not determined);
  `Rx submission`: capacity >= 2, non-null callback, `maxBuffers (== 1 for Apple) <= pool+0x34`;
  `Tx/Rx completion`: capacity >= 2; Tx completion requires `flags == 0`. The target/callback pair in Apple's classes is
  `(this, this->vtable[slot])` with slots 99 (Rx dequeue), 100 (Tx dequeue), 101 (completion).
* **Ownership.** The pool is retained by every queue and held by `AppleBCMWLANPCIeSkywalk` (state+0x38); the interface holds
  the queues in its ivars (TxSubmission array +0x78, TxCompletion +0x60, RxCompletion +0x68, Multicast +0x98). At
  `AppleBCMWLANSkywalkInterface::stop` (0xffffff800156ac34) each queue gets `disable()` (vptr+0x158), is removed from the
  work queue (vptr+0x148 of `IO80211WorkQueue`; the multicast queue via `IO80211WorkQueue::removeWorkSource`), released and its
  pointer cleared; `AppleBCMWLANPCIeSkywalk::free` (0xffffff80014d99f8) does the same for the common Rx submission queue, then
  releases the pool, frees its lock and the state block.

### 4. Request payload sizes (not determined)

The `apple80211*` request wrappers in `round3/ioctl-*.asm.txt` only admit the request (`isCommandProhibited`, interface vptr
+0xcc0 -> slot 410), safe-cast, and tail-call a virtual with the user pointer; they never touch the payload, so no size is
visible there. `getCARD_CAPABILITIES` (GET 12) forwards to `IO80211Controller` slot 412
(`AppleBCMWLANCore::getCARD_CAPABILITIES(IO80211SkywalkInterface *, apple80211_capability_data *)`). In that BCM handler the
data block is written as: dword +0 = 1, word +4 = 0xe66f, qword +7, byte +9 = 0x40, word +0xc = 0x201, qword +0xf = 0, byte
+0x17 = 0, and bit masks OR-ed into bytes +0xa..+0x16; nothing beyond +0x17 is written, so the block is **at least 0x18 bytes**.
Sizes of scan/associate payloads: not determined.

Byte map of what that handler (0xffffff80015f16ca) stores, from `round3/AppleBCMWLANCore-getCARD_CAPABILITIES.asm.txt`: +0 u32 = 1
(version); +4..+0x17 a 20-byte bit array. Constants: +4 = 0x6f, +5 = 0xe6, +6 = 0x61, +9 = 0x40, +0xc = 0x01, +0xd = 0x02; the rest of
+7..+0x17 is cleared first. Unconditional ORs: +7 |= 4, +0xa |= 4. ORs when firmware feature flag 1 is absent: +6 |= 0x10, +9 |= 1;
flag 7 absent: +6 |= 2. Everything else is conditional on `featureFlagIsBitSet(n)` for ~70 values of n, on chip/firmware state words of the
core's state block (+0x30c, +0x400, +0x40e, +0x42a, +0x1558 -> +0x10 sub-block, +0x43b8, +0x44d4, +0x477c, +0x74b6..+0x74cc) or on a
bus-layer virtual (vptr+0xa30). The meaning of individual bits is **chưa xác định**. The native stub reports the unconditional
subset plus the two "flag absent" bits (docs/TEST-NATIVE-WIFI.md, "CARD_CAPABILITIES (ioctl 12)").

### What the dumps say about creating an interface (all from `round3/`, `round4/`, `round5/`)

`AppleBCMWLANCore::createSkywalkInterface(AppleBCMWLANSkywalkInterface **out, apple80211SkywalkIfCreateParams_t *p,
IO80211VirtualInterface *)` (0xffffff800163aaf8) is not a Family virtual; its callers are not in the dumps (**chưa xác định**, needs a
xref in the KC). Its steps, in order:

1. `p`: +0 `const char *` BSD name prefix, +8 six MAC bytes (dword + word), +0x10 interface id (must be `< 0xc`), +0x14 BSD unit,
   +0x18 role (2 = the only role the registration code below handles; `AppleBCMWLANLowLatencyInterface` is created for a flag in
   the bus state instead).
2. `AppleBCMWLANSkywalkInterface::withProvider(core, id, role, logger, faultReporter)`: `OSObject_typed_operator_new`,
   `IO80211InfraProtocol::IO80211InfraProtocol(const OSMetaClass *)` (exported C2), `init()` (vptr+0x88 = slot 19),
   `IO80211SkywalkInterface::setInterfaceRole(unsigned)`, `setInterfaceId(unsigned)`, `IOService::attach(core)`. `numTx` is
   fixed to 4 (<= 4 enforced), ACs {0,1,2,3}.
3. `core->attachInterface(iface, core)` (vptr+0xdc8 = slot **443**, `IO80211Controller::attachInterface(OSObject *, IOService *)`,
   returns bool). On failure of anything later: `core->detachInterface(iface, false)` (slot **444**, `(OSObject *, bool)`), result
   `0xe00002bc`.
4. `bzero(info, 0x130)`, `IOSkywalkEthernetInterface::initRegistrationInfo(info, 1, 0x130)`, then: `+0x14 = 2`, MAC at +0x108 (dword)
   / +0x10c (word), `+0x24 = +0x28 = 0x80`, `+0xc = 3`, `+0x40 = 0` then OR-ed with 2 (property `IOPMResetPowerStateOnWake` true
   on the core's provider) and `<< 2` of boot-arg `wlan.skywalk.legacy-power-off-mode`, `+0x3c` (u16) `= 0x40` (headroom), and for
   role 2: `+0x30` = prefix pointer, `+0x38` = unit, `+0x40 |= 4`.
5. **`iface->start(core, info)`** = vptr+0x1478 = **slot 657**, a virtual *after* the Family's 656 (`AppleBCMWLANSkywalkInterface::
   start(AppleBCMWLANCore *, IOSkywalkEthernetInterface::RegistrationInfo *)`, returns bool). Not an `IOService::start`.
6. Inside that start (0xffffff800156a576): `AppleBCMWLANInfraProtocol::initWithProvider(core)` (the BCM layer's own state block,
   `this+0x128`: 0x128-byte class `AppleBCMWLANInfraProtocol`, 0x130 for the interface) -> `getInterfaceRole`, role 1 calls a virtual
   with `1` -> `IO80211InfraInterface::start(IOService *)` with the core -> the interface's work queue -> a 0x60-byte request to the
   **bus** (core ivars+0x1510, vptr+0x118) which creates pool + queues and writes them back through pointers into the interface

   `info+0x4c -= headroom` -> `registerInfraEthernetInterface(info, queues, numTx + 2, pool(state+0x50), pool(state+0x58))`,
   `0` = success. The queues are `IOEventSource`s: `IOSkywalkPacketQueue`'s vtable is `IOEventSource`'s with `disable` at slot 45.
7. The common Rx submission queue is **not** in the registered array; where Apple registers it is not visible in the interface's

### What the code does and what it knowingly does not

* The Tx submission queue factory is the plain `IOSkywalkTxSubmissionQueue::withPool(pool, capacity, queueId, owner, action, refcon,
  options)` (24H32 has no `withPoolAndServiceClass`): all four queues get the default service class. Apple's BCM subclass passes
  `{0, 0x00100080, 0x00380100, 0x00400180}[ac]` (mbuf service classes BE/BK/VI/VO) to `initWithPool`; doing the same needs a
  subclass of `IOSkywalkTxSubmissionQueue` (header generation for the queue family, not done). `isWMMSchedModelCapable` may therefore
  reject the queue set: **unverified, a load will tell**.
* Reading `round4/IOSkywalkTxSubmissionQueue-initWithPool.asm.txt` again: `initWithPool(pool, serviceClass:u32 [stored at this+0xb8],
  capacity [must be >= 8], queueId, owner, fnA, action [must be non-null], refcon, options [<= 0x1f])`. So the service class **is**
  a plain argument of the exported `initWithPool`, and 24H32 also exports two longer `withPool` overloads (`...PFjS3_PS_PjEPFjS3_S4_PKP15IOSkywalkPacketjPvESC_jj`,
  i.e. an extra `fnA` callback `(owner, queue, u32*)` and one extra trailing u32). Which trailing u32 is the service class
  is **chưa xác định** (the `withPool` bodies are not in the dumps); the 7-argument factory the stub uses reaches `initWithPool`
  with serviceClass 0 and fnA null. Options bits 0x2/0x8 set bytes at this+0x142; bit 0x4 / a global allocate extra state.
* Queue `options` is 0 and the dequeue/completion callbacks return 0 without touching packets: **what a callback must do with a
  packet is not determined** (the queues are never enabled while the datapath is unsupported).
* `enableDatapath`/`disableDatapath` answer unsupported, `getMultiCastQueue` is null, every pure handler answers
  `kIOReturnUnsupported`, `isCommandProhibited` of the controller still says 0x3a: the Family cannot reach a radio.
* `IOPMResetPowerStateOnWake` / `wlan.skywalk.legacy-power-off-mode` flag bits are not replicated (+0x40 = 4 only).
