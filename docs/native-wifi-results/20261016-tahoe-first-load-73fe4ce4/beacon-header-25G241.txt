### Reproduce

```sh
# on the Mac (or from the mounted System volume on Linux, with capstone installed):
KC=/System/Library/KernelCollections/BootKernelExtensions.kc python3 tools/kc.py     # or:
KC=/mnt/macos-sys/System/Library/KernelCollections/BootKernelExtensions.kc python3 tools/kc_vtable.py find getBeaconMsgFromWLBSSInfo
```

`tools/kc.py` exposes `disasm(start, end)` (needs `pip install capstone`); the addresses above are offsets into that KC.

### Why the old 0x40 guess broke the scan list

With `kBeaconHeader = 0x40` the IE area sat four bytes early: at `+0x40` the consumer read the flags dword as an element
header, so every element (the SSID element included) was parsed from the middle of its predecessor, and the last element
ran four bytes past the end of the buffer we posted (we sent `ie_len + 0x40` bytes where the consumer expects
`ie_len + 0x44`). The core's own AP table was fine (see `nvram-checkpoints.txt`, the `itlm3` `rx=.. ap=..` line).
