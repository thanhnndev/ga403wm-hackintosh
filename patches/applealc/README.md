# GA403WM AppleALC port (S4 + M2)

Custom AppleALC 1.9.9 resources for the ROG G14 GA403WM (SSID `1043:1024`,
ALC285 `0x10EC0285`, CS35L56 amps on `\_SB.I2CB.SPKR`). Built from the pinned
upstream reference (`build/AppleALC-reference`, commit `ff01db2`) with two
surgical changes to the PIut02 layout-33 files. The reference tree stays
pristine; patches are applied to a staging copy at build time.

## What changed and why

### S4 — woofer pin `0x17` takes DAC1 (`0x02`)
Linux quirk for this exact SSID (`ALC285_FIXUP_ASUS_GA403U_I2C_SPEAKER2_TO_DAC1`,
`build/linux-alc269.c`): `snd_hda_override_conn_list(codec, 0x17, {0x02})`.
Upstream `Platforms33.xml` routes output pin 23 (`0x17`) to DAC 3 with stream
channels 5/6, while pin 20 (`0x14`) uses DAC 2 ch 1/2. The CS35L56 DSP tuning
does the tweeter/woofer crossover, so both speaker pins share DAC `0x02`
ch 1/2 — exactly like Linux. `Platforms33.xml` here: path `[23,3]` → `[23,2]`,
channels 5/6 → 1/2. DAC 3 keeps only headphone pin 33 (`0x21`).

### M2 — second internal DMIC pin `0x13`
Upstream disables `0x13` (`0x400000f0`); only `0x12` (`0x90a60170`) feeds macOS,
which reports `num-internal-mics = 1`. The G14 mic array needs both:
- `Platforms33.xml`: new input path `[8,35,19]` (ADC 8 ← mixer 35 ← pin 19),
  bare NodeIDs, mirroring `ALC236/Platforms69.xml` (`[7,36,18]` + `[8,35,19]`).
- PinConfigs layout-33 entry: `0x13` `0x400000f0` → `0x90a60160` (internal mic,
  assoc 1 seq 6, pairing with `0x12` assoc 1 seq 7; cf. Linux
  `ALC256_FIXUP_ASUS_MIC {0x13, 0x90a60160}`).

`layout33.xml` (devices, DSP) is unchanged.

## Files

| File | Role |
|---|---|
| `patch-platforms33.py` | applies S4+M2 to pristine `Platforms33.xml`, asserts structure |
| `Platforms33.xml` | generated patched output (committed for review; regenerated by build) |
| `patch-pinconfigs33.py` | flips the layout-33 `0x13` rows to `0x90a60160` in a PinConfigs plist |
| `../../scripts/build-applealc-ga403wm.sh` | stages reference + patches, packs resources, builds `build/AppleALC-GA403WM.kext` with CLT clang |

## Install (after build passes)

EFI `layout-id` stays **33** (`alc-layout-id` 33; AppleALC publishes 7, as today —
that rewrite is upstream behavior, `kern_alc.cpp`, not our change).

1. Back up ESP: `EFI/OC/Kexts/AppleALC.kext` → `EFI/OC/Kexts-backup/AppleALC-stock-<date>/`
   (root via osascript wrapper, established pattern).
2. Copy `build/AppleALC-GA403WM.kext` → `EFI/OC/Kexts/AppleALC.kext`.
3. `python3 -I tools/occonfig.py -c /Volumes/ESP/EFI/OC/config.plist check` + ocvalidate.
4. Reboot.

## Verify (no listening tests)

- `kextstat | grep AppleALC` → 1.9.9 loaded.
- `build/alc-verb 0x13 GET_PIN_WIDGET_CONTROL` / pinconfig readback → `0x90a60160`
  (was `0x400000f0`); `0x12` unchanged `0x90a60170`.
- Codec probe (`scripts/macos-audio-codec-probe.sh`): pin `0x17` connection → DAC
  `0x02` (was `0x03`); input engines show the second DMIC path.
- `ioreg -n HDEF`: `alc-layout-id` 33, `layout-id` 7 (unchanged aliasing).

## Rollback

Restore `EFI/OC/Kexts-backup/AppleALC-stock-<date>/AppleALC.kext`, re-run
ocvalidate, reboot. No config.plist change is needed (layout-id untouched), so
rollback is one file copy.
